# ADR-015 — Immutable deal provenance and isolated DDS

Status: accepted implementation decision, 6 September 2026. Implements Phase 4 / OD-15 / OD-16; the independent experienced-player review of the WBF boundary remains pending.

## Decision

`internal/deal.Source` produces a validated deal value and provenance. Production defaults to `SecureRandom`, using the existing unbiased Fisher–Yates engine function with `crypto/rand.Reader`. `Prepared` defensively copies a validated pack. `Constraint` supports explicit per-seat HCP and suit-length ranges, validates elementary feasibility, and performs at most the configured 1–10,000 CSPRNG rejection attempts with cancellation. Exhaustion is an explicit failure, never an approximate match. The deterministic ChaCha8/SHA-256 source is compiled only with `testfixture` or `integration`; its seed is never part of provenance. Sources are injected into the application repository constructor; there is no public deal-upload, seed, or constraint command.

The WebSocket parser emits board-start intent. Inside the existing table transaction, request deduplication, revision fencing, participant/controller/owner/readiness checks run before source generation. `DEAL_REQUIRED` is an internal decision signal consumed by the repository; it is never committed as a client rejection. Successful generation is validated again, assigned a server UUID, decided through the existing aggregate, and committed with board metadata, lineup, events, snapshot, and one immutable `board_deals` record. Source failure rolls back everything and is logged as `DEAL_SOURCE_UNAVAILABLE`; it may be retried with the same request identity. A committed retry returns the stored outcome without calling the source again.

`board_deals.source_record` retains the complete original pack and source type/version plus an optional opaque UUID reference. It is private database data, not a live projection or log field. Board number, UUID, dealer, and vulnerability remain on the canonical board row, and are read together with the source record. Starting another board cannot overwrite the previous record. Reusing a stored board means reusing this immutable value and its metadata, not invoking its generator again. Prepared content may be deliberately used for separate boards, each of which has its own board identity. Legacy boards without a source record are not backfilled with guessed provenance and return analysis-not-found.

DDS is a one-request native subprocess behind `internal/analysis.Solver`. The engine imports neither analysis nor application infrastructure. The executable receives 16 validated bitmasks, dealer, and vulnerability over stdin; no cards appear in argv, files, errors, or logs. Output is bounded to 16 KiB and validated before mapping. Default capacity is one worker, no waiting queue, and a 10-second deadline. Configuration permits 1–4 workers and at most 60 seconds; HTTP write timeout must exceed the solver timeout. Cancellation terminates the subprocess. A busy worker returns a retryable response. No analysis path writes a game result, revision, event, or score sheet.

The solver is DDS 2.9.0, upstream commit `8d75755c8df81999557758c9757514edb94017bc`, downloaded with a pinned SHA-256 archive digest. The standalone executable excludes upstream `dds.cpp` DLL auto-initialization/finalization and explicitly calls `SetResources` and `FreeMemory`: linking DLL finalizers into an executable reproduces an upstream static-destruction-order crash. The build uses single-thread DDS, without a new Go/CGo dependency. The archive license ships with the binary. The default container builds and includes the solver. Unit tests run without a native build; the component gate explicitly builds the pinned executable and checks it against upstream example deals, DD tables, and dealer-par answers.

`GET /v1/boards/{boardId}/analysis` requires a valid guest session and current table membership. The durable board must be scored or passed out. Outsiders receive 404, active boards 409, unavailable/busy solvers 503, and deadlines 504. All responses use `Cache-Control: private, no-store`. Analysis returns all 20 seat/strain trick counts; makeable contracts mean the maximum undoubled level for each seat/strain with at least seven tricks. Dealer-aware par is signed `scoreNS`; sacrifice contracts explicitly carry doubled/undertrick fields. This is analysis, never the authoritative board result or one-table IMP. Phase 5 must extend eligibility to prevent revealing a shared deal while the other match room is still playing.

## Observability and verification

Operational questions: did the source fail or persistence fail; was analysis denied/busy/unavailable/timed out; how long did analysis take? Existing command logs distinguish source errors from DB errors. `board_analysis_processed` records request ID, fixed result code, pinned solver version, and duration, allowing counts/error rates and latency distributions to be derived in the existing structured-log pipeline. Raw solver errors/stderr, cards, seeds, tokens, and source references are excluded. No new telemetry provider or public debug endpoint is introduced.

Tests cover four source types, invalid/prepared/constraint failure, cancellation, defensive copies, no partial board, no generation on unauthorized/stale/duplicate commands, historical source recovery, membership/status denial, source privacy, solver timeout/process/output errors, generated API shape, and upstream golden DD/makeable/par answers. The existing pure-engine import allowlist remains the dependency guard.

Upstream references: [DDS 2.9.0 API](https://github.com/dds-bridge/dds/blob/v2.9.0/doc/dll-description.md), [golden input and answers](https://github.com/dds-bridge/dds/blob/8d75755c8df81999557758c9757514edb94017bc/examples/hands.cpp).
